## 2. Сравнение способов чтения

Программа создаёт временный двоичный файл и считает строки тремя способами: по одной строке при обходе файла; после полного `read()`; после создания списка `list(...)` из строк. Во всех случаях считается одинаковый результат. Пик выделений Python измерен через `tracemalloc`, время указано только для описания запуска, не для сравнения скорости: порядок опытов фиксирован и кэширование файла не контролировалось.

Данные искусственные: каждая строка содержит 4095 букв `a` и перевод строки, поэтому её размер равен 4096 байтам. Все строки одинаковые, распределение значений сильно отличается от реального. Размеры файлов 20 МиБ и 2048 МиБ; больший файл в 102,4 раза больше. Временный файл автоматически удаляется после эксперимента. Для запуска требуется не менее 2 ГиБ свободного места и достаточно свободной оперативной памяти для полного чтения и списка.

| Размер файла | Способ | Число строк | Пик выделений Python, байт | Время, с |
|---|---|---:|---:|---:|
| 20 МиБ | Поток | 5 120 | 17 162 | 0,017 |
| 20 МиБ | Полный `read()` | 5 120 | 20 980 146 | 0,011 |
| 20 МиБ | Список из генератора | 5 120 | 21 191 544 | 0,023 |
| 2048 МиБ | Поток | 524 288 | 17 162 | 2,563 |
| 2048 МиБ | Полный `read()` | 524 288 | 2 147 492 274 | 3,187 |
| 2048 МиБ | Список из генератора | 524 288 | 2 169 482 648 | 6,038 |

При потоковом обходе одновременно обрабатывается одна строка, поэтому при одинаковой длине строк измеренный пик почти не зависит от числа строк. У `read()` в памяти оказывается содержимое всего файла. Список дополнительно хранит ссылки и отдельные объекты строк: ленивый генератор внутри `list()` не сохраняет потоковую экономию памяти. Это пик отслеживаемых выделений Python, а не общий пик рабочего набора процесса или файлового кэша ОС. Для очень длинной строки потоковый способ также должен разместить эту строку в памяти.

## 3. Три ловушки

### 3.1. Повторное вычисление

Функция `sequence()` каждый раз создаёт новый генератор из трёх значений. Счётчик вызовов `calculate()` после первого прохода равен 3, после второго равен 6. Если один раз создать список и дважды использовать его, вычислений остаётся 3, но результаты занимают память. Повторный обход одного и того же уже исчерпанного генератора Python даёт пустой список, а не повторные вычисления: в программе получено `[2, 4, 6]`, затем `[]`.

### 3.2. Закрытый ресурс

Генератор создан внутри `with`, а обход начат после выхода из блока. Файл к этому моменту закрыт, поэтому получено `ValueError: I/O operation on closed file.` Кажется, что источник уже обработан, но создание выражения не прочитало строки. При обходе внутри `with` получены две строки `b'first\n'` и `b'second\n'`.

### 3.3. Отложенный побочный эффект

Сначала выводится `генератор создан`. Лишь при `list(values)` появляются строки `вычислено 1` и `вычислено 2`, после чего выводится `результат: [2, 4]`. Вызовы `show()` записаны при создании выражения, но выполняются при обходе. Поэтому на побочные эффекты в отложенном выражении нельзя полагаться до потребления генератора.

## 4. Сопоставление и правила

В Python объект генератора после полного обхода исчерпан. В Julia генератор по диапазону `1:3` в проверенном примере допускает повторный обход: дважды получено `[2, 4, 6]`, счётчик вычислений достиг 6. При этом `Iterators.Stateful(1:3)` сохраняет состояние: после первого обхода `[1, 2, 3]` второй дал `Int64[]`. Поведение зависит от конкретного источника, а не только от слова «итератор».

Потоковая обработка нужна, когда данные не помещаются в память или результат можно получить по частям. Материализация полезна для небольших данных при многократном обходе, если повторное чтение или вычисление дорого. Она не подходит для бесконечного потока и может занять много памяти. Одноразовость следует обозначить в имени и описании параметра, например `lines_iterator`, и не использовать такой объект второй раз без явного создания нового источника.

Проверены пустой ввод, одна строка, повторяющиеся и неупорядоченные строки, пустая строка и последняя строка без перевода строки. Потоковый и полный способы вернули одинаковое число строк. Это счёт строк, поэтому содержимое, дубликаты и порядок на результат не влияют.

## 5. Воспроизведение и вывод

Из каталога задания команда `python -X utf8 task2.py` выполняет все опыты и печатает фактические результаты. Значения времени и памяти при новом запуске могут отличаться. Временный файл создаётся рядом с программой и удаляется автоматически.

В проведённом опыте потоковое чтение файла 2 ГиБ потребовало 17 162 байта отслеживаемых выделений Python, а полное чтение около 2 ГиБ. Список из генератора занял ещё больше памяти. Отложенное вычисление полезно при последовательной обработке, но требует следить за числом обходов, временем жизни источника и моментом побочных эффектов.
