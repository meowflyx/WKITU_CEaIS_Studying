### 1.3.1. P1: список по умолчанию

Основные строки фрагмента:

```python
def add_tag(tags: list[str] = [], tag: str = "новый") -> list[str]:
    tags.append(tag)
    return tags

first = add_tag()
print(first)
second = add_tag()
print(second)
print("same:", first is second)
```

Список `[]` создается при выполнении определения функции. В обоих вызовах без аргумента используется этот же список. Первый вызов добавляет одну строку, второй добавляет еще одну. Копирования содержимого нет. Переменные `first` и `second` связаны с одним объектом, что подтверждает `is`.

Первый `print` выполняется до второго вызова, поэтому печатает один элемент. К концу опыта через `first` тоже видны два элемента. Для функции, которой нужен отдельный список на каждый вызов, вместо `[]` следует использовать `None` и создавать список внутри тела. Причина повторного использования значения по умолчанию описана в [документации Python](https://docs.python.org/3.13/tutorial/controlflow.html#default-argument-values).

### 1.3.2. P2: изменение объекта и замена локального имени

```python
def change(items: list[int]) -> None:
    items.append(2)
    items = [99]
    print("local:", items)

items = [1]
alias = items
change(items)
print("caller:", items)
print("same:", items is alias)
```

При вызове параметр `items` связан с переданным списком. `append(2)` меняет этот общий объект. Затем `items = [99]` связывает локальное имя с новым списком. Имя `items` у вызывающей стороны остается связанным с прежним списком `[1, 2]`. Присваивание `alias = items` тоже не создает копию. Поэтому у вызывающей стороны `items is alias` дает `True`.

### 1.3.3. P3: поверхностная копия

```python
source = [[1]]
copied = source.copy()
copied[0].append(2)
copied.append([3])
print("source:", source)
print("copy:", copied)
print("same outer:", source is copied)
print("same inner:", source[0] is copied[0])
```

`copy()` создает отдельный внешний список. В него переносятся ссылки на прежние элементы. Вложенный список `[1]` остается общим, поэтому добавление `2` видно в исходном списке. Добавление `[3]` меняет только новый внешний список. Здесь скопирован внешний контейнер, но содержимое вложенного изменяемого объекта не скопировано.

### 1.3.4. P4: глубокая копия и повторная ссылка

```python
from copy import deepcopy

shared = [1]
source = [shared, shared]
copied = deepcopy(source)
copied[0].append(9)
print("source:", source)
print("deep:", copied)
print("same as source:", source[0] is copied[0])
print("same inside deep:", copied[0] is copied[1])
```

В исходном внешнем списке два элемента ссылаются на один вложенный список. `deepcopy` создает новый вложенный список и сохраняет повторную ссылку на него внутри копии. Добавление `9` не меняет исходный объект, но видно через оба элемента копии. Предположение о двух независимых вложенных списках оказалось неверным. Учет уже скопированных объектов описан в [документации модуля copy](https://docs.python.org/3.13/library/copy.html).

### 1.4.1. J1: изменяемая структура

```julia
mutable struct MutablePoint
    x::Int
end

original = MutablePoint(10)
alias = original
alias.x = 20
println("original: ", original.x)
println("alias: ", alias.x)
println("same: ", original === alias)
```

`mutable struct` допускает изменение поля. Присваивание `alias = original` не создает второй экземпляр. Изменение через `alias` видно через `original`, обе строки печатают `20`. Для этого изменяемого объекта `===` подтверждает, что экземпляр общий.

### 1.4.2. J2: неизменяемая структура

```julia
struct Point
    x::Int
end

original = Point(10)
alias = original
try
    alias.x = 20
catch error
    error isa ErrorException || rethrow()
    println(sprint(showerror, error))
end
alias = Point(20)
println("original: ", original.x)
println("rebound: ", alias.x)
```

У `Point` запрещено менять поле существующего значения. Попытка вызывает `ErrorException`. После обработки этой ошибки имя `alias` связывается с новым значением `Point(20)`. Исходное значение остается `Point(10)`. Это изменение привязки имени, а не изменение поля прежнего значения.

Неизменяемое значение не требует отдельной наблюдаемой идентичности как изменяемый объект. По его сравнению нельзя сделать вывод об адресе памяти или фактическом выделении на стеке. Различие видов структур описано в [руководстве Julia](https://docs.julialang.org/en/v1/manual/types/#Composite-Types).

### 1.4.3. J3: неизменяемая оболочка с изменяемым полем

```julia
struct Box
    items::Vector{Int}
end

original = Box([1])
alias = original
push!(alias.items, 2)
println("items: ", original.items)
println("same vector: ", original.items === alias.items)
try
    alias.items = [99]
catch error
    error isa ErrorException || rethrow()
    println(sprint(showerror, error))
end
```

У `Box` нельзя заменить поле `items` другим вектором. Сам вектор остается изменяемым, поэтому `push!` добавляет `2`. Через исходную оболочку виден `[1, 2]`. Попытка `alias.items = [99]` уже меняет поле оболочки и вызывает ошибку. Неизменяемость внешнего значения не распространяется автоматически на объекты, доступные через его поля.

### 1.4.4. J4: массив значений и массив объектов

Во фрагменте используются `Point` и `MutablePoint`, определенные в J1 и J2.

```julia
values = [Point(1)]
values_copy = copy(values)
values_copy[1] = Point(9)
objects = [MutablePoint(1)]
objects_copy = copy(objects)
objects_copy[1].x = 9
println("values: ", values[1].x, " ", values_copy[1].x)
println("objects: ", objects[1].x, " ", objects_copy[1].x)
println("same arrays: ", objects === objects_copy)
println("same object: ", objects[1] === objects_copy[1])
```

Обе операции `copy` создают новые внешние массивы. В массиве значений замена элемента копии не меняет исходный элемент: получаются `1` и `9`. В массиве изменяемых объектов копируются ссылки на элементы. Изменение поля общего `MutablePoint` дает `9` через оба массива. В этом опыте различаются и типы элементов, и операции: замена элемента массива и изменение поля вложенного объекта. Сам по себе новый внешний массив не означает независимость всех вложенных данных.

## 1.6. Правило проверки чужого кода

| Язык | Что проверять | Когда изменение увидит вызывающая сторона |
|---|---|---|
| Python | Меняется объект методом или элементом либо перепривязывается локальное имя; есть ли явная копия | Изменение общего изменяемого объекта видно, локальное присваивание имени не заменяет переменную вызывающей стороны |
| Julia | `struct` или `mutable struct`; изменяемы ли поля; где применяется `copy`; что меняет функция | Изменение общего вектора или изменяемой структуры видно, перепривязка параметра не меняет привязку вызывающей стороны |
| Java | Примитив или ссылка; меняется поле объекта либо сам параметр | Передается значение, в том числе значение ссылки. Изменение общего объекта видно, присваивание параметру новой ссылки не заменяет ссылку вызывающей стороны |
| C# | Значимый или ссылочный тип; присутствуют ли `ref`, `out`, `in`; содержит ли структура ссылки | При обычной передаче структура копируется, ссылка на класс копируется без копии объекта. `ref` позволяет изменять саму переменную вызывающей стороны |

Для Python вывод подтвержден P2, для Julia правила передачи аргументов дополнительно сверены с [руководством по функциям](https://docs.julialang.org/en/v1/manual/functions/#Argument-Passing-Behavior). Правила Java и C# приведены по [документации Oracle](https://docs.oracle.com/javase/tutorial/java/javaOO/arguments.html) и [Microsoft](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/keywords/method-parameters). Код на Java и C# не выполнялся.

Справочное сравнение C#: если у структуры и класса есть целочисленное поле `X = 10`, обычное присваивание второму имени дает разные последствия. Изменение `X` через копию структуры до `20` оставляет исходное поле равным `10`. Изменение через вторую ссылку на класс дает `20` и через исходную ссылку. Это ожидаемое поведение по документации, а не фактический вывод программы этой работы.

Объект класса в обычной управляемой модели размещается в куче. Локальное значение структуры может храниться в стеке или регистрах; поле структуры внутри объекта класса хранится вместе с этим объектом, элементы массива структур находятся внутри массива в куче. Поэтому правило «структура всегда в стеке, класс всегда в куче» описывает размещение неточно. Фактическое размещение данных в опытах не измерялось. Различие значимого и ссылочного типов описано в [справочнике C#](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/builtin-types/value-types), управляемая куча в [документации .NET](https://learn.microsoft.com/en-us/dotnet/standard/garbage-collection/fundamentals).

## 1.7. Проверки и повторный запуск

В `task1.py` и `task1.jl` результаты восьми основных фрагментов проверяются утверждениями `assert` и `@assert`. Дополнительно выполняются восемь краевых проверок.

| Язык | Проверка | Результат |
|---|---|---|
| Python | Копия пустого списка | Равное содержимое, отдельный объект |
| Python | Копия списка с целым числом `10**100` | Значение сохранено |
| Python | Глубокая копия списка со ссылкой на себя | Отдельный список, собственный цикл сохранен |
| Python | Индекс `0` пустого списка | Получен ожидаемый `IndexError` |
| Julia | Копия пустого `Int[]` | Равное содержимое, отдельный массив |
| Julia | Копия массива с `Point(typemax(Int))` | Предельное значение сохранено |
| Julia | Индекс `1` пустого массива | Получен ожидаемый `BoundsError` |
| Julia | Создание `Point("bad")` | Получен ожидаемый `MethodError` |

Python использует целые произвольной точности, поэтому `10**100` является проверкой большого значения, а не максимума типа. В Julia проверяется граница типа `Int`; арифметика с переполнением в этой проверке не выполняется.

Повторная проверка из корня репозитория:

```text
python -X utf8 PLT/practice_6/task1/test_task1.py
```

Фактический вывод, код завершения 0:

```text

```

Тест запускает оба файла в новых процессах, сверяет полный вывод с `execution.txt`, проверяет отсутствие вывода ошибок и неизменность `predictions.md`. Python запускается без `-O`, иначе встроенные проверки `assert` отключаются. Флаг Julia `--startup-file=no` исключает влияние пользовательского файла запуска.

## 1.8. Вывод

Семь из восьми исходных гипотез не подтвердились. В Python присваивание и передача списка сохраняют общий объект, поверхностная копия отделяет только внешний список, а глубокая копия сохраняет повторные связи внутри нового графа объектов. В Julia изменение `mutable struct` видно через второе имя, поле обычной `struct` заменять запрещено, но содержимое ее вектора менять разрешено. Чтобы предсказать результат, нужно проверить конкретную операцию и изменяемость объекта на каждом уровне вложенности.
